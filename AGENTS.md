## Workflow base

This project uses the vendored workflow base **drax-ai-workflow** v0.3.0. The seam is
`.opencode/workflow.json`; validate it with `node .opencode/tools/base.mjs doctor .`. If the
seam is missing, these workflows are dormant: say so and stop.

`.opencode/agents`, `.opencode/commands`, `.opencode/skills`, `.opencode/packs` and
`.opencode/tools` are generated by the base. Edit the base repo, not those files. Check for
drift with `node .opencode/tools/base.mjs check .`; update with
`... update . --from <base>`; remove with `... eject .`.

`.github/skills` and `.github/agents` are a generated bridge for VS Code Copilot Chat, from
the same source. Never hand-edit them; the canonical files are under `.opencode/`. Copilot
reads this `AGENTS.md` directly, so the rules below apply there unchanged. If `.github/` is
missing, this project was installed with `--no-copilot` and only the OpenCode tree exists.

### Starting a project

A new project starts with `/start-project <idea>`. It writes an approved first spec
in the issue directory and stops before any code; if at least two council triggers
hold it asks for `/council` first.

### Hillclimb

When a task is quality-sensitive — UI, UX, visual, copy or docs — or has a clear,
measurable objective (coverage, warnings, build/test time, bundle size, response time), ask
whether to run the hillclimb workflow before implementing it directly. It is opt-in.

The gate is the 1–10 perception rubric in the `hillclimb` skill
(`references/hillclimb-rubric.md`), plus the project addendum named by the seam.

- **Below 8:** name the specific subjective flaws holding it back, fix those, and iterate.
- **8 or above:** stop and ship, unless the task explicitly demands a 10.
- **8–9 with a 10 demanded:** name what a 10 requires, attempt at most two iterations, then
  stop and report the ceiling if the score does not move.
- **Floor:** the seam's `checks` (build, test, free) must pass. A red floor cannot score 8.

The score is the only iterate/stop signal. A green floor does not earn a ship; a number
moving does not earn a ship.

### Council

For a larger feature — one where the shape is worth more than the code — run a council
before planning. Convene when at least two of these hold: a new user-facing surface; a new
subsystem, protocol, dependency or transport; it crosses a seam; it is expensive to
reverse; more than one design is credible; or the user asks.

A council is **divergence**: whether to build, what it must feel like at 8/10, and which
trade-off is accepted. Hillclimb is **convergence**: whether the built artifact is good
enough. Security is a veto lens in both; the user decides value.

`/council <proposal>` or the `council` skill. One artifact in the seam's issue directory,
which the spec links. The experience thesis travels into the spec, so the hillclimb gate
scores against intent plus the rubric.

### Working preferences

1. **Pick the approach before coding.** For any non-trivial feature, settle the approach
   with the user before writing code — offer the realistic options with a short trade-off
   each and ask; don't assume.
2. **Verify visual changes with temporary sample data.** Use the seam's seed and capture,
   look at the result, then remove the seed. The project section names the specifics.
3. **Run the free checks, always.** After any code change, run the seam's `checks` and
   report the real output — never a remembered result. Say plainly what was **not run**.
4. **Gate hillclimb on perceived quality, not statistics.** Score with the rubric from real
   evidence. A green number never substitutes for the rubric; tests and build are a floor.

### Session hygiene

One session per task; `/compact` when switching topics; prefer targeted reads; delegate
isolated work to subagents.

### Conventions

Small atomic commits with a clear scope; never commit secrets or personal data; check
`git status` before committing.

### Where things are

- Seam, precedence, update/eject, issue tracker, domain docs: the `workflow-base` skill.
- Rubric: the `hillclimb` skill.
- Security lens: the `security-auditor` subagent, on every change.

## This project

HillClimberUI is a single-user, local-only Blazor Server dashboard for driving
OpenCode runs and gated hillclimb loops against a project folder. It runs on the LAN
behind a PIN. The app, its tests and its dev scripts are described in the root
`README.md`; this section only records what an agent needs beyond the base.

### Dev loop

- The commands are the seam's `checks`: `build`, `test`, `free` and the opt-in
  `paid` in `.opencode/workflow.json`. Read them from there; do not restate them
  here.
- Stop the dev host before `dotnet test` on Windows.
- The token-spending harness (`scripts/ui`, the seam's paid check) drives real
  `opencode` runs. Run it only with explicit approval; otherwise report it as
  **not run**.
- No app change means no UI harness; say so rather than implying it passed.

### Visual verification

- Start the app with `CLIMBER_SEED` for transcript states the committed playback
  fixture can reach (see `README.md`); that fixture is product code and stays
  committed.
- Page-local state the fixture cannot reach uses a throwaway seed: clearly marked,
  uncommitted, confined to one throwaway file plus a single hook.
- Capture screenshots with the Playwright harness in the temp `climb-ui` folder at
  the seam's `verify.widths` and `verify.themes`.
- Remove the seed before the final report.

### UI quality

- The universal rubric is in the `hillclimb` skill; this project's probes 8–13 and
  caps are in [`docs/agents/hillclimb-addendum.md`](docs/agents/hillclimb-addendum.md).
- The design contract is [`docs/ui-contract.md`](docs/ui-contract.md); the art
  direction is [`docs/ui-art-direction.md`](docs/ui-art-direction.md).
- AI surfaces must reuse a documented AI Element; non-AI surfaces must reuse a
  shadcn base component.

### Council seat models

The council reuses the four agents as read-only lenses. This project routes its
seats to Surplus models; the provider is configured with a **minimum 80% discount**
floor, so a model is usable only if some seller clears that floor, otherwise the
request fails with a 404 before a token is spent.

| Model | Routable at `min80` | Seat |
| --- | --- | --- |
| `deepseek-v4.1-flash-1017` | yes | chair, shape |
| `glm-5.3-flash` | yes | experience (default) |
| `qwen3.8-flash` | yes | swap; third on every brief |
| `claude-haiku-4.5` | yes | probe only; ranked last |
| `claude-sonnet-4.6` | yes | escalation only |
| `claude-sonnet-5` | yes | risk (default) |
| `claude-opus-4.8` | **not listed** | on request only; unavailable on 2026-11-17 |
| `claude-sonnet-4.5` | **no** | — |
| `claude-haiku-5.5` | **no** | — |
| `claude-sonnet-5.5` | **no** | — |

The project implements this mix in `opencode.json`: chair and shape on DeepSeek,
experience on GLM 5.3 Flash, risk on Claude Sonnet 5.

The market moves. This table was checked against the Surplus catalog on
2026-11-17; `deepseek-v4.1-flash-1017`, `glm-5.3-flash`, `qwen3.8-flash`,
`claude-haiku-4.5`, `claude-sonnet-4.6` and `claude-sonnet-5` were still listed.
Before swapping a seat, make one one-token call to the model and confirm it
returns instead of a 404. See the `council` skill for the seat brief and rounds.

### Optional local models

Cloud is the default: chair and shape run DeepSeek, experience runs GLM 5.3 Flash
and risk runs Claude Sonnet 5. Local models are an opt-in fallback for privacy,
offline work, or unlimited throughput — **not a cost saving**: Surplus prices
DeepSeek at ~$0.038/M input, ~$0.50/M output, ~$0.0075/M cached read, so a busy
month costs a few dollars, usually less than the electricity to run a local GPU
for the same work.

OpenCode auto-discovers Ollama at `http://127.0.0.1:11434`, so no provider config
is needed. Install Ollama, then pull a model that fits the machine:

```sh
ollama pull qwen3:14b      # ~9 GB, ~30-47 tok/s on a 16 GB card
ollama pull gpt-oss:20b    # ~14.5 GB, fast tool use, shorter context
```

Pulled models appear in `/models` next to the cloud ones. To send one agent to a
local model, set its `model` in a project-level `opencode.json`; leave cloud
everywhere else. Prefer an explicit model entry with a context `limit`, `cost: 0`,
and `capabilities.tools: true`, because discovery may not supply a limit and
compaction depends on it.

Treat the model choice as machine-specific: pick it per project, not in the base.
